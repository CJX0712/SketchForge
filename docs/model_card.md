## 1. 系统标识

| 项 | 值 |
|---|---|
| 名称 | SketchForge（固定预算数据流摘要与预算分配系统） |
| 类型 | 确定性优先的程序库 + CLI + 可审计 benchmark 报告生成器 |
| 输入 | 数据流（int64 / float / str 键）+ 总字节预算 B + 查询负载 |
| 输出 | 四类查询的估计值 + `benchmark.json`（含每个 sketch 的实测字节、误差、耗时、审计结论） |

## 2. 用途

### 2.1 适用场景

- **固定内存预算**下需要同时回答多类流式查询（基数 / 分位数 / 频率 / 重尾），且预算总量是硬约束（嵌入式、边缘、常驻进程、SLA 内存上限）。
- **查询负载的边际收益差异明显**：不同查询族的误差对预算的弹性（`c_i`）不相等，此时把预算从低弹性查询挪给高弹性查询有确定收益。
- **数据生成过程（DGP）随时间漂移**：段间弹性变化时，按段重拟合 + 重分配优于任何固定分配。
- **要求可复现与可审计**：所有数字必须能定位到"哪个后端、哪个参数、实测占多少字节、误差落在什么界内"。
- **离线/无网环境**：Tier-1 路径零下载可跑完整 demo。

### 2.2 不适用场景

- 单查询、预算无约束、只追求绝对精度 → 直接用 Tier-0 的对应 sketch，本系统增加的是**分配层**价值，不是单查询精度。
- 需要精确答案（不允许概率性误差）→ sketch 天生是近似结构，任何"零误差"需求都应走全量计算。
- 需要 merge 的分布式基数合并 → **CPC / HLL 在 datasketches 5.2.0 中无 `merge` 方法**【架构实测】，需改用 theta sketch 族（本系统未纳入 MVP）。
- 数据率极高且要求纳秒级单条更新 → Python 层每调用开销未做优化；本系统的吞吐指标是**批次吞吐**，不是单条延迟。
-  adversarial 输入下的健壮性保证：本系统不提供对抗性输入（刻意构造的哈希碰撞攻击）下的保证。

## 3. 对比阶梯（预注册，不得事后更改成员或角色）

| 角色 | 成员 | 说明 | 是否可实现 |
|---|---|---|---|
| 消融对照 | **均匀分配** `UniformStrategy` | 证明"分配器"这个组件确有贡献 | 可实现 |
| **主门禁基线** | **全局静态最优分配** `StaticOptimalFrozen` | 在校准 seed 集上 grid search 后**冻结**的单一分配；均匀分配是它的次优特例 | 可实现 |
| **旗舰（本系统）** | 按段拟合弹性 + 边际收益均等 `ElasticityWaterFilling` | 每段重新拟合 `ErrorLaw` 并重分配 | 可实现 |
| 金标准（上界参照） | **分段最优分配** `PerSegmentOptimal` | 每段各自 grid search——用到了每段自身的信息，实际不可实现 | **不可实现** |

**泄漏防护**：校准 seed 集（用于冻结静态最优）必须与评测 seed 集**不相交**。否则基线会变成"看过答案的对手"，反而强于分段最优，整个阶梯失效。

## 4. 查询族、指标与方向

| ID | 查询 | 指标 | 定义 | 方向 |
|---|---|---|---|---|
| Q1 | 基数 | `cardinality_rel_err` | `\|est − true\| / true` | 越小越好 |
| Q2 | 分位数/秩 | `quantile_norm_rank_err` | `\|rank_est(q) − rank_true(q)\| / N` | 越小越好 |
| Q3 | 点查频率 | `frequency_rel_err` | `\|est − true\| / max(true, 1)` | 越小越好 |
| Q4 | 重尾项 | `heavy_hitter_f1` | 相对精确 top-k 的 F1 | 越大越好 → 以 `1 − F1` 参与聚合以统一方向 |

**聚合口径（主门禁）**：`G = ∏_i e_i^{w_i}`，其中 `e_i = err_i / ε_i`，权重等权 `w_i = 1/4`。
`ε_i` 取"均匀分配份额下该方法的理论误差界"（`error_bound_declared`），无理论界者退到 `SPEC_TOLERANCE` 表并在报告中标注 `spec_source`。

## 5. 结构性限制（诚实声明）

### 5.1 单查询族不声称超越 SOTA

**本系统对任何单类查询都不声称精度超越对应的 SOTA sketch。** 已实现的分位数与基数模块直接采用 datasketches 的工业实现（KLL / CPC / HLL），我们不做、也不声称对其算法本身的改进。

文献中的公认结论（**本系统卡未重新验证，引用请以原始论文为准**）：

- **分位数**：KLL 的空间复杂度与该类问题的已知下界在同阶（相差常数至对数因子）。本系统不声称在单查询层面改进它。
- **基数**：HLL 的相对误差约 `1.04/√m`，与已知下界的间隙被认为是 `log log n` 量级的常数因子问题。本系统同样不声称改进。

### 5.2 本系统唯一声称的优越性

1. **系统级：在总预算 B 固定、需同时回答四类查询的前提下，分配策略优于"全局静态最优分配"基线**（判据见 §10）。
2. **单查询非劣**：在**同等字节预算**下，本系统为每类查询选择的模块，其误差不显著劣于该类查询的 SOTA 单查询 sketch。
   - 操作化定义：`err_i(本系统模块 @ 分配到的字节) / err_i(SOTA 单查询 sketch @ 同一字节) ≤ 1 + τ`。
   - **τ 尚未冻结**（建议 `0.10`）。在 τ 冻结前，任何"非劣"结论只能以"实测比值 + 原始数字"形式披露，不得写成通过/不通过。

### 5.3 为什么这样划界

把"分配层"与"算法层"分开声明，是为了让**优越性声明可被证伪**：分配层的收益可测（同一个方法、同一批数据、只改分配向量）；算法层的改进则需要与 KLL/HLL 的实现本身对打，那不是本系统的工作，也不应混进 headlines。

## 6. 平稳 DGP 上的期望改进 ≈ 0 是理论必然

若数据生成过程**平稳**（段间弹性不变），则：

- 各段拟合出的 `ErrorLaw` 相同 → 旗舰每段的分配解相同 → **旗舰退化为"全局静态最优分配"**；
- 此时 `G_ratio = 1.00`，改进为 0。这不是实现缺陷，而是**数学必然**：静态最优就是平稳情形下的最优解。

同理，若四类查询的弹性 `c_i` **全部相等**，则均匀分配已经是最优（AM-GM 取等条件），任何分配策略的改进都是 0。

> **审计红线**：若在某个被标为"平稳"的数据集上报告出大幅改进（例如 `G_ratio ≤ 0.9`），第一反应**必须是**——① 口径被挑选（换了聚合方式/归一化方式/权重），或 ② DGP 泄漏（探针段混入了评测段、校准 seed 与评测 seed 相交）。**不得**把它当作旗舰的能力证据。反之，旗舰的预期收益只能来自**段间弹性漂移**，评测集必须包含非平稳 DGP（`drift_abrupt` / `drift_gradual` / `elephant_mice` / `low_card` 等）才有意义。

## 7. 确定性披露

### 7.1 分位数族在 Tier-0 上跨进程随机

【架构实测，`datasketches 5.2.0`】`kll_floats_sketch`、`req_floats_sketch`、`quantiles_doubles_sketch` **在同一进程内两次构造、灌入完全相同的数据，估计结果也不同**（KLL 归一化秩误差：499 / 493；REQ：495 / 493；quantiles：499 / 500）。根因是 C++ 侧压缩使用 `random_device`，Python 绑定未暴露 seed 入口——**这是库的固有性质，不是本系统的 bug**。

处理方式（不掩盖、不删除）：

- 这些方法的 `DETERMINISTIC=False`，记录中如实标记；
- 报告层面对其 value 使用哨兵 `"<stochastic>"` 参与 canonical digest（G2）；
- 精度上用 `error_bound_declared × safety`（`safety=3.0`）做误差带约束（G3）；
- **它们不进入主门禁的分配实验**（主门禁两侧必须都是确定性方法）。

**G3 的松紧度自评**【由 Pilot 实测数据推算】：以 `out_p1.txt`（R=20 seeds, N=50 000）为例，KLL 实测 `err_mean` 约为库声明界 `ds_nre` 的 **13.5%**（k=50）到 **18.4%**（k=800）；改用 `err_max`（最坏 seed × 最坏分位点）后为声明界的 **49%–65%**。因此：

- 用 `err_mean` 配 `safety=3.0` → 门限约为实测的 16 倍，**极宽松**，只能拦住灾难性失效，不具备精度约束能力；
- **建议 G3 改用 `err_max` 判定**（均值会掩盖尾部失效），并把 `safety` 收紧到 `1.5`。**该建议尚未冻结，当前实现仍为 `mean × 3.0`。**

### 7.2 CPC / HLL 无 merge

【架构实测】`cpc_sketch` 与 `hll_sketch` 在 5.2.0 中**没有 `merge` 方法**。因此：

- `SUPPORTS_MERGE=False`，`merge()` 抛 `E304`；
- 涉及合并一致性的用例对这两个方法标 `skipped`（`skip_reason="merge_unsupported"`），**不填任何数值**；
- 需要合并语义的基数场景请改用 theta sketch 族（MVP 未纳入）。

### 7.3 重尾族 Tier-0 只能用 `frequent_strings_sketch`

【架构实测】`frequent_items_sketch.serialize()` **强制要求 serde 参数**，无参调用抛 `TypeError`。为保持"预算 = `len(serialize())`"的统一测量口径，重尾族 Tier-0 一律使用 `frequent_strings_sketch`（键为 str），并配 `preprocess/encode.py` 的稳定编码；真值 top-k 必须在同一编码上计算，否则 F1 不可比。

### 7.4 其他确定性约束

- 唯一 seed 入口 `core.seed.set_all()`；`SeedState.derive(tag)` 派生互不重叠子流；
- 分配器是纯函数，**零 RNG**（有专门的"禁用 RNG 后仍能运行"测试）；
- 拟合走**闭式 log-log 最小二乘**，不用 `scipy.curve_fit`（【架构实测】换初值后结果在第 10 位起不同，不是良定义函数）；
- 禁止内置 `hash()`（`PYTHONHASHSEED` 运行时不可改）。

## 8. 两条已发现并强制披露的性质

1. **纯幂律区间内，最优分配 `b_m = (Σ_{i∈served(m)} w_i c_i)/λ` 与 `a_i` 和总预算 B 无关。** 即"自适应"只在下界（`b_min`）与饱和（`floor`）约束生效时才真正体现为预算的函数。**不得对外表述为"随预算动态调整"。**
2. **归一化常数 ε 对几何平均口径免疫。** `argmin ∏(err_i/ε_i)^{w_i}` 中 `−Σ w_i log ε_i` 与分配变量无关 ⇒ 最优解与 ε 的选取完全无关，不存在"调 ε 让旗舰赢"的空间；而求和口径的 argmin 依赖 ε，是可调旋钮。这是选几何平均作主口径的数学理由。
   - 实锤对照【架构实测，合成参数】：同一"优化误差和"的分配，在**原始误差求和**口径下 +5.5%，在**归一化后等权求和**口径下 −10%；在几何平均口径下 `G_ratio = 1.0862`（劣于均匀）。**归一化即加权，不是中性操作。**

## 10. 门禁（预注册，跑完不得回调）

| # | 判据 | 阈值 | 状态 |
|---|---|---|---|
| G-1 | `max_s G_ratio_s < 1.0` | 全 seed 严格优于静态最优基线 | 已冻结 |
| G-2 | `mean_s G_ratio_s ≤ 1 − δ` | **δ = 0.15**（即 `G ≤ 0.85`） | **已预注册，不因结果调整** |
| G-3 | `mean_s (G_旗舰 / G_分段最优) ≤ 1.02` | 旗舰接近不可实现上界 | 已冻结 |
| G-4 | `\|predicted_ratio − mean_s ratio\| ≤ 0.03` | 模型一致性（防止靠运气赢） | 已冻结 |
| 消融 | `G_旗舰 / G_均匀 ≤ 0.95` | 证明分配器组件确有贡献 | 已冻结 |
| no-harm | `gate_no_harm = False` | 允许部分查询变差以换取聚合改善 | 已冻结 |

**no-harm 关闭的理由**：零和预算下，"全查询不劣化"与"严格超越基线"数学上不可兼得——弹性全相等时均匀已最优（AM-GM 取等），弹性不全等时最优分配必然让低弹性查询变差。强行加 no-harm 会把最优解拉回均匀附近，等于让护栏亲手把旗舰退化成基线。`WaterFilling(no_harm=True)` 作为第二行照实报出，不合并进主结论。

**统计口径**：3 个 seed 不构成有意义的显著性检验（n=3 功效不足），因此**不使用 p 值**，改用"全 seed 一致 + 均值门槛 + 报告 mean±std"。不得把结果包装为"统计显著"。

**披露要求**：四个 `err_i^旗舰 / err_i^基线` 必须原样打印；数据集层面同样等权并单独报告每个数据集的 G（防止单一数据集扛起聚合值）。δ 已于跑数前预注册为 0.15；**若最终不达标，如实判 C 级阻断并落 `BLOCKED.md`，不做任何口径微调来凑数**。

## 11. 已知限制与失败模式

| # | 限制 / 失败模式 | 表现 | 处理 |
|---|---|---|---|
| L1 | 弹性退化（`c_i ≤ 0` 或 `r² < 0.9`） | 预算增加但误差不降 | 该查询退回均匀份额，记 `law_degenerate`；若全部退化则 `allocation_separation` 判 FAIL，实验判空虚 |
| L2 | 预算吃不满（`budget_utilisation < 0.5`） | sketch 尺寸涨不上去（如 REQ 小预算无可行参数） | 真实 skipped，禁止硬塞伪数字 |
| L3 | 指标对预算不敏感（`budget_response < 0.02`） | 分配与否结果一样 | 判实验空虚，`G_ratio` 不得写进 headline |
| L4 | 探针与评测段分布漂移 | 拟合律预测与实测偏差大 | G-4 拦截；另设 `probe_eval_law_consistency` 审计告警 |
| L5 | 校准 seed 与评测 seed 相交 | 静态最优基线"看过答案"，阶梯失效 | 流程纪律 + 报告记录两集合 |
| L6 | 单条更新延迟 | Python 层 per-call 开销大 | 走 `update_batch` 向量化；吞吐指标以批次计 |
| L7 | 重尾项 `1 − F1` 恰为 0 | `log(0)` 污染拟合 | 取对数前 `max(err, 1e-6)`，被 clamp 点如实上报 |
| L8 | 成本口径退化 | 分母取 B / sketch 个数等共享常量 → `c ≡ 1.00` | 通用规则：分母为共享常量即判 `vacuous_denominator` FAIL |
| L9 | 分位数族非确定 | 跨进程不可复现 | G2 哨兵 + G3 误差带 + 不进主门禁 |
| L10 | CPC 序列化随基数增长 | 按参数推算的预算偏小 | 预算一律在 ingest 后实测 |
